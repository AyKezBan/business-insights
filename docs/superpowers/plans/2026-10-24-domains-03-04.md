## Global Constraints

- Генеративные модели — только из списка кейса и через выданный доступ.
- Командный бюджет — эквивалент 500 руб. в день по материалам кейса.
- Минимальная версия Python существующих компонентов — 3.11; импорт Левона требует PostgreSQL 17+.
- Новые feature-ветки создаются от актуальной `develop`; функциональное имя предложения — `feature/material-ingestion-bank-evidence`.
- Все 9 банковских PDF — сканы: 64 страницы без извлекаемого текстового слоя. Нельзя ограничиться PDF text extraction.
- Дата отсечения — дата анализируемого события; при её отсутствии текущая UTC-дата с явной оговоркой. Окно актуальности текущего подтверждения — 180 дней; будущие источники исключаются.
- Позиция банка допускается только по проверенному фрагменту реального PDF; отсутствие подтверждения отображается явно.
- Секреты, сырые CSV, экспорт чата, полные PDF и сгенерированный корпус не коммитятся. Синтетические фикстуры явно маркируются.
- Сохраняются существующие `InsightRequest`, `Insight`, `Answer`, `run_id` и имена инструментов. DTO расширяются совместимо; JSON Schema экспортируются из Pydantic, не редактируются отдельно вручную.
- Обычные тесты работают offline; интеграционные проверки OCR, RSS, PostgreSQL и LLM документируются отдельно.
- До согласования плана разрешены только исследование и документация. Implementation начинается после явного согласования пользователя.

## Review Focus

1. Скан, где OCR меняет цифру, `%`, единицу или отрицание: такой текст не должен стать подтверждённой позицией банка. Тесты задач 2–3 и ручной gold-прогон задачи 10.
2. У документа неизвестная/старая дата или он опубликован позже события: расширенный поиск и уточняющий вопрос не должны обходить ограничения. Тесты задач 7–8.
3. Один URL обновился либо два источника похожи, но расходятся в числе: сохранить версии и избежать неверного объединения/старого кеша. Тесты задач 5 и 8.
4. Исключённое утверждение осталось в `what_happened` или свободном `Answer.text`: проверять все выходы и отдавать только подтверждённый текст. Тесты задачи 8.
5. Ошибка источника/записи после подготовки части файлов: текущий корпус остаётся целым, другая компания/версия не получает чужие данные. Тесты задач 6, 8, 10.

### Task 5: Дедупликация, несколько источников и обновление события

**Владелец:** Мурад. **Оценка:** 1–2 ч. **Spec:** §9.4; A06–A08.

**Files:** Create `materials/dedup.py`, `tests/test_news_dedup.py`.

**Interfaces:**

- `canonicalize_url(url: str) -> str`: убрать fragment и известные tracking-параметры, сохранить параметры, меняющие публикацию.
- `normalize_news_text(text: str) -> str`: Unicode/whitespace-нормализация, без удаления чисел, пунктуации величин, дат и отрицаний.
- `merge_news(existing: list[NewsEvent], versions: list[SourceVersion], incoming: list[RawNews], *, observed_at: datetime) -> NewsImportResult`; `NewsImportResult` содержит `events` и `versions`. CLI задаёт единый observed_at batch до загрузки; это timestamp нового наблюдения, не дата публикации.
- ID источника зависит от канонического URL и content hash; event map сохраняется между импортами. Один URL при обновлении сохраняет `event_id`; идентичные тексты разных URL объединяются со всеми source refs. Нечёткое совпадение — кандидат для явной группировки, не автоматическое слияние.
- У URL одна активная ревизия. Точный повтор текущего текста не меняет revision/first_seen_at; новый возврат к историческому тексту после своей правки создаёт следующую revision. Primary event — active version с максимальным first_seen_at, tie-break лексикографически меньший canonical URL; все новые версии одного batch имеют общий observed_at. Дата публикации — из выбранного primary, без подмены временем получения. Старый saved-news (retrieved_at раньше first_seen текущей версии) не откатывает её; две разные версии одного URL без порядка в одном batch отклоняются как ошибка входа.
- A17+B17 → E, затем A18 → тот же E с A18 primary, active refs A18/B17 и `conflicts` по spec §9.4; старый A17 — история. Повтор B17 не откатывает E и не снимает конфликт. Анализатор получает оба текста и unresolved conflict, а не молчаливое «B подтверждает 18».

- [ ] Написать проверки: повтор batch не меняет counts/IDs; два URL с одинаковым текстом дают 1 event и 2 sources с разрешаемыми текстами; тот же URL с `17%→18%` сохраняет event ID и две версии с полными разными текстами; похожий другой URL с `17%/18%` не склеивается; `повысил/не повысил` не склеивается; meaningful query parameter сохранён.
