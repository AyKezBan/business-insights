# Интеграция с ML

Источник контрактов — закреплённая версия ML-сервиса. `MlContracts` сохраняет исходные поля `snake_case`, неизвестные значения и десятичную точность денежных показателей. Публичные DTO API и модели хранения отделены от ML-контрактов.

Локальные JSON Schema проверяют запросы и ответы. Дополнительно сверяются идентификаторы компании, события и роли, ссылки на источники и доступность признаков. Эти проверки не подтверждают фактическую достоверность выводов AI.

## Ошибки и длительные операции

Клиент ограничивает время запроса и размер ответа, не повторяет POST автоматически. После таймаута завершение операции ML неизвестно.

- HTTP `422` и прочие `4xx` — отклонение запроса; `429` — ограничение частоты; `5xx` и ошибки связи — недоступность сервиса.
- Некорректный JSON, нарушение схемы или несовпадение идентификаторов — недопустимый ответ ML.
- HTTP `200` со статусом `failed` или `no_answer` сохраняется как отдельный исход анализа, а не как транспортная ошибка.

Уточняющие вопросы требуют контекста в памяти ML. После рестарта, обращения к другому процессу ML или раннего сбоя анализа возможен `404`. Бэкенд сообщает об отсутствии или истечении контекста, даже если сам инсайт сохранён в PostgreSQL.

## Сохранение доказательств и ограничений

ML DTO, JSONB и публичный API сохраняют идентификаторы claims, версии и выдержки источников,
издателя, точность даты, first-seen/retrieved, конфликты, outcome/error/request и контекст корпуса.
Публичный UUID операции отличается от logical event ID и ML insight/run ID.

`evidence_spans` в claims/impacts сохраняются через JSONB и публичные `evidenceSpans`,
включая вопросы к инсайту. Каждый фрагмент содержит opaque source ID, SHA-256 и
полуоткрытые границы `[start,end)` в Unicode code points. Старые записи без этого
поля получают пустой список. При наличии хеша у SourceRef он должен совпадать с
хешем фрагмента; отсутствие legacy-хеша допустимо. Java и интерфейс не вырезают
текст заново по смещениям — показывается уже проверенный текст утверждения ML.

Выручка 0..999 сохраняется; ровно 1000 остаётся placeholder. В ML передаются год,
статус и company/group scope, доступность ФТС, известный период платежей и quality notes.
Отсутствие сведений ФТС не доказывает отсутствие торговли. Платёж не доказывает роль
поставщика или покупателя; неизвестная групповая выручка остаётся неизвестной.
Устаревшие предупреждения о уже исправленном поведении ML не понижают результат.

Схема и ссылки проверяют структуру и происхождение, но не заменяют смысловую приёмку.
