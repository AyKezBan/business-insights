# Backend API

Java 21, Spring Boot 3.5.7, Maven, JDBC/PostgreSQL. Сервис собирает профиль компании, запрашивает персонализированную аналитику ML и предоставляет ленту, вопросы и обратную связь.

`PostgreSQL business_insights → Java CompanyProfile → ML HTTP → PostgreSQL backend_api → API`.

Таблицы импорта читаются без изменений; результаты, входные снимки, происхождение данных и трассы сохраняются в отдельной схеме `backend_api`. [Архитектурные диаграммы](docs/architecture.md), [правила профиля](docs/profile-rules.md), [ограничения ML](docs/ml-compatibility.md), [зависимости и лицензии](../THIRD_PARTY_NOTICES).

## Локальный запуск

Нужны JDK 21, Maven 3.9+ и доступный PostgreSQL 17+ с набором `data-import` версии `0.3.0`. Пользователю БД нужны чтение `business_insights` и права создания/изменения своей схемы `backend_api` для Flyway. ML-сервис нужен для генерации инсайтов и ответов на вопросы; остальные API можно использовать без него.

PowerShell из корня репозитория:

```powershell
mvn -B -ntp -f backend-api/pom.xml '-Dmaven.test.skip=true' '-DskipTests' package
$env:DB_JDBC_URL = 'jdbc:postgresql://localhost:5432/business_insights'
$env:DB_USER = 'business_insights'
$env:DB_PASSWORD = '<пароль БД>'
$env:BACKEND_DEMO_TOKEN = '<случайный токен>'
$env:BACKEND_DEMO_PERSON_ID = 'F_1' # существующий ID
$env:ML_BASE_URL = 'http://localhost:8000'
java -jar backend-api/target/backend-api-0.1.0.jar
```

Запросы `/api/v1/*` требуют `Authorization: Bearer <токен>`; без настройки токена доступ закрыт. [Конфигурация](src/main/resources/application.yaml), [переменные окружения](.env.example). Локальный Java-процесс не читает `.env` автоматически. `/health` проверяет только процесс.

## API

[OpenAPI](src/main/resources/static/openapi.yaml) доступен также по `/openapi.yaml`. Основной путь: выбор компании → приём события → анализ → опрос операции → просмотр инсайта. Есть скрытие, обратная связь, уточняющие вопросы и трассы; действия сохраняются локально без доставки в CRM.

Анализ и вопросы возвращают `202`, `Location` и `Retry-After`. `Idempotency-Key` предотвращает повтор одинакового запроса. Роль задаётся явно. Недостаточные данные, отсутствие ответа и ошибки различаются; пустая лента допустима. Сортировка — по оценке влияния ML, а не по проверенной релевантности.

## Контракты с ML

В `src/main/resources/ml-contracts/*.json` находятся JSON Schema обмена Java-бэкенда с ML-сервисом:

- Вход ML: `insight-request.schema.json` и `question-request.schema.json`.
- Выход ML: `insight.schema.json`, `answer.schema.json` и `trace-event.schema.json`.

Схемы включаются в JAR и используются для проверки структуры запросов и ответов во время работы.

Ошибки корпуса из ML сохраняют отдельный код в публичном ответе или ошибке операции:

| Код backend | HTTP при синхронном запросе | Повтор по действию пользователя |
| --- | --- | --- |
| `ML_CORPUS_EVENT_MISMATCH` | 409 | Нет; проверьте выбранную версию |
| `ML_CATALOG_CURSOR_MISMATCH` | 409 | Нет; обновите список материалов |
| `ML_CORPUS_UNAVAILABLE` | 409 для недоступной закреплённой версии, 503 для временно недоступного корпуса | Только при 503 |
| `ML_CATALOG_UNINITIALIZED` | 503 | После публикации каталога |

Асинхронная операция остаётся доступной для чтения и сохраняет этот код и `retryable`; её POST автоматически не повторяется.
Клиент распознаёт только согласованные сочетания кода и статуса. Текст ошибки ML не передаётся пользователю; неизвестные ответы получают общую контролируемую ошибку.

## Ограничения

- Один экземпляр backend и ограниченная очередь. После перезапуска незавершённые операции получают `FAILED/BACKEND_RESTARTED`; автоматического повтора ML-вызовов нет. После таймаута завершение ML неизвестно, а после рестарта ML контекст вопросов может исчезнуть.
- `/events` принимает готовые внешние события. Сбор новостей и наполнение банковской библиотеки находятся за границей этого сервиса; доступность первоисточников зависит от переданных ссылок.
- Доступ по bearer и связям ФЛ–ЮЛ демонстрационный: связь не удостоверяет полномочия и не определяет роль. Для внедрения нужны банковская авторизация, TLS и политика доступа/хранения диагностических данных.

Проверки: `mvn -f backend-api/pom.xml test`. Для реального PostgreSQL round-trip укажите
`BI_JDBC_TEST_URL=jdbc:postgresql://127.0.0.1:55433/postgres`, `BI_JDBC_TEST_USER` и
`BI_JDBC_TEST_PASSWORD` отдельного тестового PostgreSQL17+ (не рабочей БД). Harness
создаёт случайную БД, применяет Flyway и удаляет только свою БД после проверки.
Без URL тесты БД явно отмечаются NOT_RUN/skipped; это не подтверждение DB gate.
