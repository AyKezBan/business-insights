В ML-finalize появились полезные guards для текущего/предыдущего значения конкретных CBR indicators, но они не закрывают общий случай и применяются в `check_claims`, а не делают общий event-fact entailment доказанным.

## 4. Что переиспользовать из ML-finalize

`materials/` и bank retrieval core не изменились между двумя frozen snapshots. D03/D04 не нужно переписывать OCR, immutable snapshots, exact dedup, version ordering, review gates и BM25. В ML-finalize уже есть существенная работа Ангелины, которую надо принять в целевой сборке:

| Уже реализовано в ML-finalize | Применение и остаточный предел |
| --- | --- |
| Request idempotency/409, bounded cache, сохранение insight/state на диск, QA после restart; prompt/git/model versions в trace | Переиспользовать для handoff и воспроизводимости. Это не управление обновлением ленты; idempotency по прежнему request_id намеренно возвращает прежний ответ |
| `as_of` в request, future event validation, отсечение related news и запрет расширения среза моделью | Переиспользовать для historical demo и отрицательных временных кейсов; явно согласовать режим «на дату события» и «на текущую дату» |
| UI card/clarification adapter, source IDs/blocks/claim kinds; Backend contract tests | Переиспользовать при подключении Java/UI. Наличие adapter unit test не доказывает браузерные URLs/полный feed |
| Profile rules: FTS ≠ import/export, self transfers ≠ counterparties, платежная связь ≠ поставщик/покупатель, неизвестная роль группы; guards неизвестных условий договора и персональных investment commands | Сохраняют смысл данных на выходе. Не заменяют содержательную персонализацию и общую проверку участников/отрицаний |
| Нормализация чисел с пробелами/млн/млрд; guards current/previous CBR key rate/FX | Полезные regressions; не считать общим решением semantic grounding |
| D05 manifest runner, PASS/FAIL/BLOCKED/NOT_RUN, versions, M7/M8 и пустая manual rubric | Переиспользовать вместо второго оценочного runner. Автоматический PASS проверяет mechanics; поля ручной rubric остаются `null` до оценки Тимуром |
| OpenResearch: официальные CBR indicators/press, allowlist fetch, TTL cache, profile-derived plan | Уже есть on-demand получение, поэтому фраза «в ML нет актуальных источников/TTL» устарела. Но это отдельный путь от immutable ingestion: пресс-source ID основан на URL; article cache TTL 30 дней, feed 30 минут, live indicators 15 минут, исторические ответы 30 дней. `retrieved_at` OpenDocument не переносится в SourceRef; исходные research revisions не публикуются в `CorpusSnapshot` |

Последняя строка задаёт конкретный D04 integration risk: исправление статьи по прежнему URL может быть скрыто длительным article cache, а наблюдение из кеша получает текущий `retrieved_at` в research result. Нужны фикстуры cache-hit/fresh-fetch/corrected-body и явная политика; отсутствие планового scheduler не следует путать с отсутствием on-demand источников.

## 6. Совместная передача и право объявить готовность

Мурад может подписать **«подготовка материалов и поиск готовы в указанном корпусе и режиме даты»**, когда F01–F04, их regressions и handoff package выполнены. Пакет: corpus revision/counts/statuses, review/gold IDs без полного частного текста, команды импорта, обновления и диагностики, source locator/URL contract, negative fixtures и список оставшихся ограничений.

Ангелина подписывает корректное использование evidence и персонализацию/QA (F05, применение ML-finalize). Левон подписывает профиль/Java transport/storage/feed/внешние routes, Тимур — UX и бизнес-полезность/holdout. Приёмка одного слоя не передаёт его смысловую ответственность другому, но и не закрывает пользовательский сценарий без остальных.

Для общей отметки **«D03/D04 приняты в продукте»** требуется один общий acceptance manifest с F06–F08: точные версии, входы, expected behavior, run/insight IDs, все source links, ручные verdicts и подписи владельцев. Обязательная совместная демонстрация: новый event → два различающихся профиля → реальный bank influence либо честное отсутствие → открытая исходная страница → QA → повтор/обновление → trace. При ошибке файла/сети остаётся последний рабочий snapshot с понятным ограничением.

**Открытые блокеры:** A10 semantic acceptance; A03 browser page navigation; A09 новый материал через общий Java/UI путь; A13 reproduction другим участником; единая freshness/update policy для snapshot и on-demand research. Технический offline baseline и узкий gold зелёные. Не следует откатывать их или переписывать готовые механизмы, но и объявлять ими весь продукт готовым нельзя.
