# Приёмка материалов

`bank-retrieval-gold.jsonl` — 10 запросов с ID реальных фрагментов и датой отсечения. Запросы и ожидаемые страницы заданы **до** запуска поиска по визуально сверенному PDF. Это небольшой regression gold по 4 документам, а не измерение качества всей банковской аналитики.

`bank-review.json` — 11 проверенных утверждений: только ID, hash и решения, без полного текста PDF. Сверены четыре страницы: ключевая ставка (стр. 1), потребление (стр. 2), 7М26 (стр. 2), инфляция (стр. 1). Для consumption стр. 2 нужна описанная в [инструкции](../docs/material-ingestion.md) ручная коррекция `25 6. п.` → `25 б. п.`; иначе hash изменённого утверждения не совпадёт и оно останется pending. Прогноз 13,5% заменён сентябрьским 14,0% только с даты публикации нового документа. Оба исторических текста сохраняются.

```sh
python ml-service/eval/run_bank_retrieval.py --store /absolute/materials
```

Критерий: минимум 8/10 попаданий в top-3 и пустой результат трёх запросов без покрытия. Runner выводит revision и IDs, без приватного текста. Реальный запуск 24.10.2026: 10/10; 3/3 без покрытия. Другой cutoff или корпус требует нового отчёта.

На время разработки сохранены 12 реальных статей ЦБ. Первые 2 — development, следующие 10 отложены до оценки; полные статьи остаются локально вне Git. Проверки holdout: непустой первичный текст, исходный URL, публикация отдельно от получения, стабильные IDs при повторе. Финальный live-прогон использует 2 другие отложенные новости × 3 синтетических профиля, не реальные клиентские CSV. Фактически 5 limited и 1 failed; A10 не принят, результаты — `live-acceptance-2026-10-24.json`.

Результаты и незакрытая общая приёмка: [materials-acceptance.md](../../docs/materials-acceptance.md). Fake LLM в offline-тестах проверяет интеграцию, а не смысловое качество модели.
