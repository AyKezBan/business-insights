# Frontend

Пользовательский интерфейс: выбор компании и роли, просмотр материалов и готовых инсайтов, уточняющие вопросы и обратная связь. В общем Docker-стеке взаимодействует с Java Backend API через same-origin gateway.

## Общий запуск

Из корня репозитория выполните `./stack init`, укажите в локальном `.env` папку CSV и пользователя `BACKEND_DEMO_PERSON_ID`, связанного с компаниями в этих данных. Затем используйте `./stack materials-up` для запуска с подготовленным корпусом либо `./stack up` для базового стека. Подготовка корпуса и регулярный сбор описаны в [инструкции инфраструктуры](../infra/README.md).

Адрес по умолчанию — http://127.0.0.1:8088; порт задаётся через `WEB_PORT`. Импорт, PostgreSQL, ML и Java запускаются вместе с интерфейсом. Для генерации нужны настройки шлюза модели на сервере. Ключ модели и серверный bearer не помещаются в браузерный код.

## Рабочий сценарий

1. В профиле выберите доступную компанию и должность. Java проверяет доступ по связям серверного пользователя с компаниями; сохранённый выбор повторно сверяется с текущей сессией.
2. Откройте бизнес-события. Каталог исходных материалов отделён от готовых инсайтов. Анализ выбранного материала запускается явным действием пользователя для его компании и роли.
3. Во время анализа интерфейс отслеживает созданную операцию. Повторное открытие продолжает её чтение; готовый результат не требует повторной генерации.
4. В карточке различаются факт, проверенная аналитика банка, вывод и гипотеза модели. Сохраняются все утверждения, источники и сведения о проверенных цитатах. Ограниченный результат или отсутствие данных показываются явно.
5. Откройте оригинальную статью или PDF на указанной физической странице. Ссылка на PDF закрепляет исходную версию корпуса. Для воспроизводимости доступны идентификаторы запуска, утверждения, источника и точного фрагмента.
6. Задайте уточняющий вопрос. QA использует контекст и версию источников родительского анализа. Оценка и отметка открытия сохраняются на сервере и восстанавливаются после перезагрузки.

Выбор компании и роли сохраняется в браузере для текущего пользователя. Недоступная компания, смена пользователя или повреждённые настройки приводят к восстановлению из актуальной сессии. Эти настройки не заменяют серверную проверку доступа.

Подробный сквозной сценарий и границы проверки: [materials-e2e.md](../docs/materials-e2e.md). Фактические результаты приёмки: [materials-acceptance.md](../docs/materials-acceptance.md).

## Отдельная демонстрация

Для самостоятельного просмотра синтетических экранов из этой папки запустите `python server.py` и откройте http://127.0.0.1:8766. Нужен Python 3.11+, сторонние пакеты для сервера не требуются. Другой порт: `python server.py --port 8770`; остановка — Ctrl+C. Этот способ явно выбирает демонстрационные данные. Ошибка Java API в общем стеке не переключает его на демонстрацию.

## Проверки

Из папки `frontend`, с установленным окружением проекта:

```sh
python -m pytest -q tests
for suite in tests/test_*.cjs; do node "$suite"; done
```

Проверки включают транспорт Java API, операции и повторное открытие, каталог материалов, сохранение контекста, источники, точные фрагменты и обратную связь. Скриптовые ответы в offline-тестах проверяют интеграцию; качество живой модели оценивается отдельно.
