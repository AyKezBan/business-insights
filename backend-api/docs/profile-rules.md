# CompanyProfile: расчёты и ограничения

Источник структуры PostgreSQL: закреплённая версия `data-import`, схема `business_insights` версии `0.3.0`. Java только читает таблицы; JSON ML собирается в `CompanyProfileService`, импорт не изменяется. Выручка — RUB за 2025 год.

| Признак | Формула / источник | Неизвестное и границы |
| --- | --- | --- |
| `revenue_rub` | `revenue_company` при `revenue_status=observed` | Только ровно 1000 — заглушка; 0 и прочие корректные значения сохраняются. NULL не заменяется нулём. |
| `group_revenue_rub` | Всегда NULL: консолидированного показателя нет | Доступный состав неполон. Сумма известных выручек ЮЛ остаётся отдельной диагностикой, не консолидированной выручкой; порог крупного бизнеса по ней не применяется. |
| `employees` | Совпавшие непустые ФНС/СПАРК; либо единственный заполненный источник | При расхождении NULL. Оба исходных значения и статус разрешения сохраняются. Без выбора предпочтительного источника и усреднения. |
| `foreign_trade` | `true` только при `fts_flag=true`; иначе NULL | Исходный false хранится в provenance и не означает отсутствия торговли. Страны передаются отдельно, без направления импорта/экспорта. Конфликт флага и стран остаётся явным. |
| `products.*` | Прямое соответствие семи исходным флагам, RKO → settlement | NULL / true / false различаются; отсутствующий продукт в этом банке не говорит о других банках. |
| `ownership` | `okfs_name` | `negativemark` — достоверные сведения о ключевом собственнике; хранится отдельно и не считается риском. |
| География | ML city/region = регистрация `company_profile.city/region` | `person_company_link.city_name/rc_name` остаются географией обслуживания в provenance. Роль/владение/место проживания ФЛ из связи не выводятся. |
| Набор для расчётов платежей | Только строки `ml_eligible=true` с валидными обязательными полями, без ambiguous ID | External ID допустим для потока; его неизвестные атрибуты остаются NULL. Исключённые строки, причины и source rows сохраняются вне ML-признаков. |
| `counterparties[].amount_rub` | Сумма eligible non-self `pay_amt` по ID и направлению, относительно анализируемой компании | incoming = компания получает; outgoing = отправляет. Это финансовые потоки, отношения покупатель–поставщик не устанавливаются. Нулевые наблюдения сохраняются. |
| `counterparties[].share_of_flow` | Числитель = сумма этого контрагента и направления; знаменатель = все eligible non-self суммы **этого направления** | Знаменатель 0 или отсутствие наблюдений → NULL. Это доля наблюдаемого снимка, не оценка полной деятельности. Decimal128 для деления, суммы точные BigDecimal. |
| `self_transfer_share` | Eligible self сумма / (eligible incoming non-self + outgoing non-self + self), self один раз | При положительном знаменателе отсутствие self строк даёт наблюдаемую долю 0; это не утверждение об отсутствии переводов вне снимка. Пустой/нулевой знаменатель → NULL. |
| `same_group` | Равенство двух известных `group_id` | Если любой ID группы неизвестен → NULL. |
| `group_member_okveds` | Уникальные известные коды прочих доступных ЮЛ той же группы | Не утверждает полноту группы. Source rows всех доступных участников сохраняются. |
| Достаточность | Есть хотя бы один пригодный бизнес-факт: ОКВЭД/выручка/численность/возраст/стадия/собственность/регистрация/FTS/страны/поток/продукт/групповые ОКВЭД или переданные пользователем сведения | ID, CL_TYPE и GROUP_ID сами по себе недостаточны. Отсутствие ОКВЭД не блокирует анализ иных известных признаков. Конфликтная численность сама по себе фактом для ML не становится. |
| Диагностики `incomingNonSelfRub`, `outgoingNonSelfRub`, `selfRub` | Точные суммы `pay_amt` eligible incoming non-self, outgoing non-self и self строк соответственно. Знаменатель не применяется | Каждая пустая выборка → NULL; реальные наблюдаемые нули → 0. Только наблюдаемый снимок. |
| `eligibleOperations` | Сумма `pay_cnt` всех eligible строк компании, self один раз; BigInteger. Знаменатель не применяется | Нет eligible строк → NULL; реальная сумма 0 сохраняется. Это количество операций в доступной части снимка. |
| `observedRows` / `eligibleRows` / `excludedRows` | Число относящихся к компании исходных строк / строк, вошедших в расчёт / строк вне расчёта. `observedRows=eligibleRows+excludedRows`. Знаменатель не применяется | 0 означает пустое соответствующее множество строк в загруженном снимке, не отсутствие деятельности вне него. |
| `selfRowsIncludingExcluded` | Число строк с payer=beneficiary=companyId, включая excluded. Знаменатель не применяется | Известный счётчик строк снимка; 0 не утверждает отсутствия self переводов за неизвестный полный период. |
| `availableMemberRevenueSumRub` / `membersWithObservedRevenue` | Сумма корректных observed `revenue_company` доступных участников той же группы / число таких участников; знаменатель не применяется | Сумма пустой выборки → NULL, счётчик → 0. Реальные нули учитываются, ровно1000 исключается. Сумма частичная, не консолидированная. |

Агрегаты пустого набора строк — NULL; сумма реально наблюдаемых нулей — 0. Год начала и окончание платежного периода неизвестны; описание «с 1 января» сохраняется из metadata. Покрытие платежей и состав группы неизвестны, год платежей не приравнивается к году выручки.

`ProfileSnapshot.provenance` хранит metadata с полным source manifest/хешами, исходные поля компании и качество, обе численности, регистрацию/обслуживание, доступную часть группы, **все** относящиеся к компании строки платежей (включая исключённые и self), их качество и отображение ML `counterparties[i]` → source rows/знаменатель. Другие `synthetic_f` не выдаются. Порядок counterparties детерминирован по ID/направлению, без сокращения списка. Сортировка и перенумерация внутри закреплённого ML остаётся известным ограничением интеграции.

Сборка профиля — read-only REPEATABLE READ транзакция; до первого SELECT берётся ACCESS SHARE на таблицы в порядке импортера, чтобы замена набора через TRUNCATE не смешала снимки. Ошибки SQL/ожидания ограничены общим query timeout; транзакция имеет timeout 30 секунд. Доступ к компании проверяется отдельно по связи ФЛ–ЮЛ, роль поступает явно из API. Для ambiguous/external профиля и CL_TYPE, отличного от CLIENT, анализ не запускается. Схема/валюта/отчётный год должны совпадать.
