# Интеграция с ML

Источник контрактов — закреплённая версия ML-сервиса. `MlContracts` сохраняет исходные поля `snake_case`, неизвестные значения и десятичную точность денежных показателей. Публичные DTO API и модели хранения отделены от ML-контрактов.

Локальные JSON Schema проверяют запросы и ответы. Дополнительно сверяются идентификаторы компании, события и роли, ссылки на источники и доступность признаков. Эти проверки не подтверждают фактическую достоверность выводов AI.

## Ошибки и длительные операции

Клиент ограничивает время запроса и размер ответа, не повторяет POST автоматически. После таймаута завершение операции ML неизвестно.

- HTTP `422` и прочие `4xx` — отклонение запроса; `429` — ограничение частоты; `5xx` и ошибки связи — недоступность сервиса.
- Некорректный JSON, нарушение схемы или несовпадение идентификаторов — недопустимый ответ ML.
- HTTP `200` со статусом `failed` или `no_answer` сохраняется как отдельный исход анализа, а не как транспортная ошибка.

Уточняющие вопросы требуют контекста в памяти ML. После рестарта, обращения к другому процессу ML или раннего сбоя анализа возможен `404`. Бэкенд сообщает об отсутствии или истечении контекста, даже если сам инсайт сохранён в PostgreSQL.

## Вопросы для согласования

В закреплённой реализации `tools/profile.py` обнаружены следующие ограничения:

- `_known_revenue` отбрасывает все значения `≤1000`. Java исключает только ровно `1000`, сохраняя реальные нули и остальные корректные значения.
- При отсутствии выручки группы масштаб оценивается по выручке юрлица. Это не подтверждает консолидированный масштаб группы или принадлежность к крупному бизнесу.
- Направления входящих и исходящих платежей получают подписи «покупатель» и «поставщик», хотя платежи доказывают только финансовое взаимодействие.
- После сортировки контрагенты перенумеровываются: ссылка `counterparties[i]` может указывать на другой исходный элемент. Java сохраняет отправленный снимок и происхождение данных, не переставляя их ради сокрытия расхождения.
- Кеш анализа событий использует только `event_id`. Поэтому бэкенд запрещает повторное использование идентификатора с другим содержимым события.

ML-признаки внешней торговли упоминают импорт и экспорт, но страны ФТС не устанавливают направление торговли. Отсутствие сведений ФТС также не доказывает отсутствие торговли.

Бэкенд сохраняет происхождение и признаки качества вне ограниченной ML-схемы и передаёт предупреждения вместе с результатом. Соответствие схеме не означает соответствия бизнес-требованиям.
