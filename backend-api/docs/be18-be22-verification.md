## Выполненная проверка

- Offline-компиляция Java 21: `mvn -o -B -ntp -f backend-api/pom.xml -Dmaven.test.skip=true -DskipTests compile` — BUILD SUCCESS. Цели test/package и приложение не запускались.
- Синтаксический разбор AST трёх изменённых Python-файлов без исполнения API и агента.
- Шесть общих JSON Schema совпадают с генерацией текущих Pydantic-моделей; все шесть ресурсных копий совпадают с общими побайтно. Проверка загружала только определения моделей, не приложение.
- Наборы полей десяти Java ML records совпадают с соответствующими моделями ML.
- OpenAPI и application.yaml разобраны SnakeYAML с запретом дублирующихся ключей. Разрешены все 115 локальных ссылок; девять публичных DTO сверены с описанными свойствами. Проверка не создавала Spring context.
- Статически просмотрены миграция, порядок блокировок, фиксация версии, идемпотентность, прекращение устаревшей очереди и обработка результатов уже выполняющегося анализа.
- `git diff --check` — без ошибок.

Тесты, сервисы, контейнеры и LLM-запросы не запускались. Миграция к БД не применялась. Динамическая работоспособность HTTP/SQL, гонки в реальной БД и качество релевантности этой проверкой не подтверждены.

Для трекера подготовлены Done/100% и дополнения к исходным комментариям пяти тикетов. При упаковке сохранены все 21 исходная часть XLSX, стили, проверки данных, формулы и диаграммы; перенесены 15 изменённых ячеек и только зависимые вычисленные значения счётчиков/карточек и кеша диаграммы. Done-счётчик подготовленной версии — 77 из 102. Визуальная проверка использует исходное оформление. На листе Kanban уже присутствуют заглушки `__xludf.DUMMYFUNCTION` от экспорта Google Sheets; они сохранены, их динамическая раскладка по колонкам не исправлялась. Авторитетные статусы находятся на листе «Задачи».

Windows запретила изменение исходного файла в `no-scope`. По последующему указанию пользователя итоговая копия сохранена в корне репозитория как `ALFA_Kanban_Project_Tracker_BE18-BE22.xlsx`; исходный файл не изменён. Копия совпадает с проверенным пакетом по SHA-256.

## Оставшиеся ограничения

Отбор использует начальные правила, а не обученную или откалиброванную модель. Обновление ленты вызывается явно; планировщика и подписок на все компании нет. Новый подготовленный корпус подключается существующим процессом запуска ML. Известные старые версии корпуса не откатывают события, но для ранее не встречавшегося содержимого нет внешнего монотонного номера события. Потерянные прежним Java-адаптером доказательства не восстанавливаются задним числом. Полный переход на отдельную ветку ML остаётся в BE-13.

Рабочие правила API и ограничения подробнее описаны в [feed-refresh.md](feed-refresh.md) и [ml-compatibility.md](ml-compatibility.md).
