# Схема PostgreSQL

SQL выполняется по порядку: [01_schemas.sql](../sql/01_schemas.sql), [02_tables.sql](../sql/02_tables.sql), [03_indexes.sql](../sql/03_indexes.sql). Все таблицы находятся в `business_insights` и содержат один текущий набор данных.

[Диаграмма всех таблиц, полей и связей](SCHEMA_DIAGRAM.md).

| Таблица | Ключ | Содержание |
| --- | --- | --- |
| `dataset_metadata` | `singleton=true` | Хеш набора, сведения об исходных файлах, время загрузки и описание периода. |
| `company_ref` | `synthetic_u` | Все валидные ID компаний и статус доступности профиля. |
| `company_profile` | `synthetic_u` | 24 поля компании, статус выручки, страны и признаки качества; ссылка на реестр и номер строки исходного CSV. |
| `person_ref` | `synthetic_f` | ID физлиц из пригодных связей. |
| `person_company_link` | `source_row` | Связи ФЛ–ЮЛ и их география; ссылки на реестры, ключ — номер строки CSV. |
| `payment_snapshot` | `row_id` | Участники, сумма, счётчик и признаки качества; ссылки на реестр компаний, ключ — номер строки CSV. |

Исходные CSV не дублируются в БД; `source_row` и `row_id` сохраняют логический номер записи без заголовка.

Деньги — `NUMERIC` без фиксированной шкалы, счётчики и номера записей — `BIGINT`, флаги — nullable `BOOLEAN`, ID и градации — `TEXT`, списки — `TEXT[]`. Пара участников платежа не является уникальным ключом.

Индексы покрывают группу компании, обе стороны связей и платежей.
